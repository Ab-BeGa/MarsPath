# Проверка координат и расстояний Езеро

- **Дата проверки:** 14 ноября 2026 года
- **Исходные точки:** `points/jezero_points.csv` — координаты из таблицы задач MarsPath.
- **Результат:** преобразование выполнено в CRS самого USGS GeoTIFF; обе точки попали в ожидаемые ячейки исходного DEM.

## Как преобразуются координаты

В GeoTIFF записана марсианская равнопромежуточная проекция (equirectangular) на сферу Mars 2000. Код берёт радиус и параметры проекции из CRS GeoTIFF, переводит широту и восточную долготу из градусов в радианы и вычисляет:

```text
x = x₀ + R · cos(φ₁) · (λ − λ₀)
y = y₀ + R · φ
```

Здесь `R = 3 396 190 м`, `φ₁ = 18.4663°`, центральный меридиан `λ₀ = 0°`; `x₀` и `y₀` — смещения из CRS (в этом файле равны нулю). Это координаты Марса из метаданных продукта, а не земная WGS84. Попытка передать широту/долготу в земную CRS отвергается.

## Расстояние между базой и научной остановкой

В проекции DEM разность координат составляет `ΔX = −433.42098 м` и `ΔY = +292.82886 м`. Прямая длина в плоской сетке:

```text
sqrt(ΔX² + ΔY²) = 523.07025 м ≈ 523 м
```

Поскольку CRS GeoTIFF выражена в метрах, расстояние сначала приводится к метрам через коэффициент единиц CRS, а затем считается по X/Y. Скрипт интерактивного профиля использует ту же функцию расчёта. Это расстояние по прямой в карте; оно не является длиной пути по рельефу.

## Проверка и файлы

- `scripts/preprocess_dem.py` содержит перевод координат Марса в CRS растра и расчёт расстояния в метрах.
- `profile_mars.py` использует ту же функцию расстояния для выбранных на карте точек.
- `tests/test_preprocess_dem.py` проверяет контрольные X/Y, направление восточной долготы, расстояние 523.07025 м, индексы пикселей и чтение реального GeoTIFF.

Повторить проверку тестами из корня репозитория:

```powershell
python -m unittest discover -s tests -v
```

DEM с шагом 20 м ограничивает разрешение проверки. Контроль индексов и прямого расстояния не удостоверяет точность полевой привязки или проходимость маршрута.
